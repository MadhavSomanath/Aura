# Aura — UX Case Study

A product-management case study of a UI/UX upgrade to Aura, a spaced-repetition flashcard app. The study screen was crowded, and the numbers on screen contradicted each other.

**Deck:** [Aura-UX-Case-Study.pdf](Aura-UX-Case-Study.pdf) (19 slides)

## What's inside

| Section | Slides |
|---|---|
| Setup | Cover, TL;DR, context, approach |
| Discover | Audit evidence (real iPhone simulator screenshots), four themes: trust, core loop, noise, polish |
| People | Proto-personas: Maya (exam crammer), Daniel (busy professional), Priya (lapsed learner) |
| Journeys | One five-stage journey map per persona, with an emotion curve, pains and opportunities |
| Define | Six user stories with acceptance criteria (MoSCoW), design principles, impact vs effort grid |
| Deliver | Shipped before/after of the study screen; proposed v2 Today screen, three-tab structure and catch-up mode |
| Measure | North star (weekly active review days), per-persona input metrics, guardrail, validation plan and risks |

## Notes

- The personas are **proto-personas** built from a hands-on audit, not from interviews. The last slide sets out how to validate them.
- The quick wins shipped in [PR #1](https://github.com/MadhavSomanath/Aura/pull/1): honest due counts, a Show Answer step, pinned grade buttons with swipe, and due-only sessions.
- The v2 screens are low-fidelity mockups and haven't been built. Mockup figures are illustrative.
